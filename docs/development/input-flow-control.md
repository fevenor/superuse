# 人工鼠标流控

## 问题与依据

只有发送窗口仍不能解决持续过载：输入位移的产生速度长期高于 HID 写入速度时，要求补发全部历史计数必然使浏览器积压。此前 32768 计数阈值会主动关闭输入连接，服务端随后以 human_input_closed 进入 human_hold。扩大阈值只会延后暂停并增加延迟。

2026-10-17 检索的主流实现：

- [noVNC rfb.js](https://github.com/novnc/noVNC/blob/master/core/rfb.js)：MOUSE_MOVE_DELAY 为 17ms；高频移动更新最新位置，经定时器节流；按钮事件先刷新待发移动。
- [PiKVM 鼠标说明](https://docs.pikvm.org/mouse/)：相对模式会产生大量事件，可通过 Squash mouse moves 合并向量，文档同时说明这可能影响鼠标加速度。
- [PiKVM mouse.js](https://github.com/pikvm/kvmd/blob/master/web/share/js/kvm/mouse.js)：相对增量限制到 HID 范围，可集中发送并请求 squash；按钮前刷新移动。

本项目参考这些设计原则自主实现，不复制上述项目源码。相对 HID 计数不是绝对坐标，过载时无法同时保证完整历史位移、固定延迟和有限缓冲。本次选择响应性与持续控制；MCP 的显式相对动作及服务端已接收报告的语义不变。

## 页面策略

1. 相对移动每 16ms 采样，分配 sequence 前合并同按钮状态、无滚轮的连续移动。
2. 最多四条报告等待 written/coalesced/rejected；accepted 不回收窗口。单条 HID 位移仍在 ±127 内。
3. 连续待发向量每轴最多 254 计数，按比例缩小以保持方向，即最多两条待发报告。空闲发送窗口可立即承接另外四条报告，单次大幅高 DPI 事件也有固定预算。
4. 饱和向量遇到反向输入时优先表达新方向。最后更新超过 50ms 的未发送纯移动直接过期，恢复写入后不补发陈旧轨迹。
5. 按钮变化单独保存，键盘、按钮、滚轮事件按序发送，不随移动过期。即使 DOM mousemove 携带了未见过的按钮变化，也先保存独立状态事件。
6. 位移压缩和过期不关闭 WebSocket、不撤销租约、不自动交还 agent。真实断连、失权、设备故障与非移动状态事件队列异常溢出仍执行原来的释放屏障。

50ms 是待发移动的新鲜度阈值，不承诺目标端延迟；已经发出的四条报告仍受网络、串口和目标处理速度影响。串口写成功仍不等于目标 UI 已确认。

## 验证

`node tests/web/browser-input.test.cjs` 运行实际页面事件处理器，使用确定性时钟和终态回执，不打开硬件：

- 1000Hz 输入、2/20/100ms 每报告写入，各持续模拟 120 秒；队列有界，人工租约不丢失。
- 高频移动后的键鼠释放顺序与有限报告等待，饱和反向、停顿后过期、遗漏 DOM 按钮事件、正常小位移计数。
- 巨大单次位移不触发暂停；失权丢弃未发送输入，不跨连接重放。

真实设备的快速移动手感与跨 PC 网络表现需要使用新包验证，自动化结果不能替代实机结论。
