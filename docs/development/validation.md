## 鼠标坐标模式修复的实机验证（2026-10-19）

- 修复背景：厂商确认默认应使用绝对坐标（相对仅限移动设备/多屏），"绝对不可用"为串口控制侧问题。根因（当日实机定位）：设备持久化坐标模式（device-info payload[25]，1=相对/2=绝对）按报文类型方向性门控，且**切换必须按厂商时序"写模式（kind 5）→ 立即发送新模式匹配零报文"完成**——省略零报文会把鼠标管线卡入中间态（0x04/0x05 均被丢弃、键盘正常、串口重连无效，需设备重启解卡），历史"绝对不可用"误判由此而来。
- 实机通过（SuperKVM 固件 0.9.16，活屏视觉验证）：附着后 State `device_mouse_mode` 与 `/v1/status` 脱敏 `device` 诊断块正确；**运行时模式切换经产品事务两次 0.6 秒完成**（写→零报文→重查校验），绝对/相对原生拖动均画出选择框（帧差 1.6–4.7 与拖动路径包围盒证据）；跨模式报文被丢弃（相对下 0x04、绝对下 0x05 均为噪声级）；零位移 0x05 在绝对模式不移动指针也**不能释放按钮**（据此 fence 中和改为键盘零 + 0x05 零 + 0x04 零于最后写入位置）；已知相对模式时绝对工具提交即拒（`DEVICE_MOUSE_MODE`）；重连后模式重查不残留。
- 复刻厂商"重启 KVM"（kind 10）并实机验证：重启写 → 本机串口断开 → supervisor 按原身份重连 → 设备信息确认（真实源必须等到 device-info 回执才算恢复）。作为远程场景的独立恢复能力保留；常规切换无需它。
- 附带实现：串口 actor 5 秒设备信息心跳（厂商 webapp 同款 keepalive，诊断常新）；kind 0 通用回执消费（rsp_code≠0 → 明确拒绝）。
- 回归：52 契约用例、Ruff、前端回归、默认 pytest 245 通过 / 16 hardware deselected。本轮未做固件/配置复位类操作；证据图与 JSON 存于本地 artifacts/hardware/mouse-mode/（含目标画面截图，不入 Git）。

- 使用正式 0.2.0 ZIP 解压副本，用户通过托盘开启局域网访问，两个入口实际绑定本机局域网 IPv4 地址；浏览器及官方 MCP SDK 均通过该地址访问，而非回环地址。
- 浏览器密钥登录、未登录/错误密钥拒绝、1920×1080 真实视频持续到达、事件及输入 WebSocket 通过。实际非安全 HTTP 环境中 `crypto.randomUUID` 不可用，页面请求 UUID 后备实现、接管及交还正常。
- 局域网 Streamable HTTP MCP 返回真实设备状态、1280×720 截图及对应 1920×1080 原始尺寸。两个独立 LAN MCP 会话和本机 stdio 会话正确互斥；页面接管后旧输入拒绝，其他会话返回 HUMAN_CONTROL；交还后另一会话可申请及释放。
- LAN 不暴露本机设备管理及界面签发入口，登出后旧浏览器身份失效。测试仅获取画面和切换控制权，未向目标输入文字或鼠标操作。专用浏览器及测试实例正常退出，设备句柄和 LAN 监听释放。
- 按维护者确定的验收标准，本机局域网 IP 补测通过即满足本版本 LAN 验收；不要求额外第二台机器，外部防火墙及网络可达性不纳入本次产品发布门槛。
- 正式版本与 rc3 的运行实现一致，仅版本及发布说明更新；rc3 已通过的 256 项源码回归与真机输入验收仍适用，正式 ZIP 单独通过 9 项发布包验收。CH9329 真机未测、当前目标绝对鼠标及相应校正落点限制继续保留。

## 正式版保持唤醒托盘状态修复（2026-11-09）

- 收到保持唤醒无法开启的反馈后，当前正式实例的本机接口成功开启，返回 `keep_awake=true`、`active=true`、`error=null`，页面显示 Windows 唤醒请求已生效。检查时保存偏好为关闭，覆盖配置文件中的开启值，符合既有优先级；没有发现 Windows 电源 API 失败证据。
- 用真实 Windows 原生菜单复现：pystray 0.19.5 在点击回调返回后立即生成菜单，设置任务仍在后台执行，最终后台开启但菜单仍未勾选。改为每次显示菜单前在托盘线程重新生成，覆盖异步完成及网页修改；同时捕获异步回调异常并记录。
- 新增原生菜单回归，用事件控制异步时序，验证完成后勾选、外部关闭后取消勾选及失败不假报成功。两项托盘定向回归通过；此前运行的单元及管理接口测试 164 项通过。本次没有改动电源请求实现或目标输入协议。
- 修复包交付后，用户确认问题已修复。修复后的托盘及管理接口定向测试 7 项通过；源码、wheel 与 ZIP 内容检查通过。按用户要求提交代码，保留 0.2.0 版本号。

完整验收方法见[测试与验收](testing.md)。实机报告只记录脱敏结论；截图、原始日志和真实配置保留在仓库之外。
