# 测试与验收

## 1. 验证层级与授权

默认 CI/pytest 只运行 schema、纯逻辑、模拟设备与本地服务测试，不枚举后打开任何硬件。真实测试同时要求：显式 `-m hardware`、`SUPERUSE_ALLOW_HARDWARE_TESTS=1`、真实模式配置、唯一匹配设备，以及当前会话已有的实机操作授权。标记本身不能代替 fixture 检查开关。

设备已连接/厂商 WebApp 正常仅证明硬件基础，不证明 Superuse 或上游候选通过。模拟测试、串口写成功、目标 UI 视觉确认分别报告。测试前停止占用同一设备的厂商页面和其他测试程序；本应用只显示占用错误，不强杀第三方进程。

可以使用用户指定的临时测试窗口和不敏感文档。禁止重放其他目标的旧坐标动作或对现有业务窗口批量输入；开始前查看当前目标画面，在可回退环境中操作。不做 OTA、配置写、格式化、关机或测试外文件操作。

## 2. 单元与竞态测试

使用 FakeClock、FakeSerialActor/可阻塞 transport、FakeCapture；状态变换和排序通过可控 latch/event 调度，不用随机 sleep 等竞态。

| ID | 用例 | 必须证明 |
|---|---|---|
| C01 | idle→agent、同 session 重入 | 仅一份有效租约，重入不释放当前输入 |
| C02 | 两个 agent 同时申请/输入 | 只有一个成功；败者无任何报告 |
| C03 | 文本输入中人工抢占 | 旧后续报告不再发送；两个中和报告先于新 owner 输入 |
| C04 | 检查授权后、实际 write 前发生接管 | actor 顺序/临界区封住 TOCTOU |
| C05 | 抢占时有一个写入阻塞 | 有界等待/失败恢复；不假确认 human |
| C06 | 旧 job finally / WS blur / close 迟到 | 不释放新 owner 的键或按钮 |
| C07 | 两个人接管、fence 回调乱序 | 较旧 ticket 不覆盖较新状态；最后有效请求所有权明确 |
| C08 | human WS 断开、TTL 到期 | human_hold，agent acquire 仍失败 |
| C09 | human handback 后旧 agent 请求 | 必须新 acquire，旧 lease 仍拒绝 |
| C10 | renew 与 takeover 交错、过期 lease renew | 不复活旧 lease |
| C11 | broker instance 改变 | 旧 lease/basis/job 不能被新实例接受 |
| C12 | 队列溢出/key_up 无法入队 | 明确背压/owner fence，无静默粘键 |
| C13 | 输入取消/超时/部分完成 | 计数正确，不重放，不声称回滚或 UI 成功 |
| C14 | 相同 request_id 重试与不同 body 冲突 | 单次副作用；窗口内不能提前逐出结果 |
| C15 | 不完整 ASCII/未知键/超 6 键 | 第一包前拒绝，不只拒绝后半段 |
| C16 | shutdown 与正在接管交错 | stopping 不被旧回调恢复为 ready/owner |
| C17 | 连续人工 mousemove、重复/缺号 sequence | 不占持久 Job 缓存，不重复发包，队列与回执有界 |
| D01 | 协议黄金向量、短写和噪声 | 正确 checksum/长度/重同步；无自动输入重发 |
| D02 | 多串口/多视频、索引变化 | 唯一身份定位；不打开内置相机 |
| D03 | 设备断开/同设备重连/身份改变 | 故障撤销；恢复不续旧任务或选错设备 |
| D04 | 视频变尺寸、停帧与卡死关闭 | basis/lease 失效；不堆积采集线程 |
| V01 | 缩放/letterbox/DPI/边界像素 | 图片坐标映射正确，越界明确报错 |
| V02 | 低速观看者、多个截图客户端 | 最新帧策略，编码复用，内存队列有界 |
| V03 | MCP 截图和元数据 | 同一帧、正确尺寸、有效 JPEG 和 basis |

## 3. 本地服务与 MCP 集成

| ID | 用例 | 必须证明 |
|---|---|---|
| I01 | 全模拟模式启动、输入、看图、接管 | 不打开真实句柄；UI/截图元数据标明 simulated |
| I02 | agent 尝试声明 human/调用 takeover、恶意 Origin、缺 CSRF | 全部拒绝；无写报告 |
| I03 | 官方 SDK client 启动 stdio bridge 并调用所有工具 | 工具 schema 与返回类型正确，stdout 只有 MCP |
| I04 | 两个独立 MCP stdio 桥共用 broker | 一个串口/相机，会话隔离与错误码正确 |
| I05 | MCP 取消/桥退出/HTTP 丢响应 | 作业取消、租约回收或 RESULT_UNKNOWN，不盲重试 |
| I06 | broker 重启、runtime 更新、凭据轮换 | 桥不采信旧 instance，不泄漏新令牌 |
| I07 | API 未知字段、超长消息、非法帧头 | 有界拒绝，不分配无界内存/挂死服务 |
| I08 | 通知不支持的 MCP host | 每次输入仍能观察失权，不依赖后台唤醒 |
| I09 | 同浏览器两标签页、旧页关闭/刷新 | page session 独立；旧页失焦/断开不影响新页 owner |

先用官方 SDK client 完成协议验收，再按用户实际使用的两个 agent 客户端做兼容验证。未实际运行某客户端时不能写入支持列表。

## 4. 硬件最小闭环

对新设备、固件或采集后端重新验证时，执行以下步骤。当前脱敏结果见[验证状态](validation.md)，不能把一次验证继承到所有环境：

1. 锁定上游提交、导入来源和许可，使用显式选定设备，不启动上游裸 TCP 控制端口。
2. 验证 DirectShow 与可选 MSMF 的实际设备、首帧、尺寸、FPS；记录后端映射，不能只记录索引。
3. 人工查看与单次点击/组合键，检查物理键码、目标输入法和焦点；验证释放报告（特别 0x05 零位移）。
4. 同一采集源向人工页面和截图消费者供图，不重复打开设备。
5. 做最小 Windows onedir 打包试验：原生 DLL/页面/键码资源可加载，无需实现完整托盘即可检验依赖路径。
6. 在 `docs/development/validation.md` 记录实际结果、时间、硬件/软件版本与问题，证据置于本地 artifacts/。失败说明具体阻碍，并提出 adapter 替代，不凭猜测继续宣布候选通过。

## 5. 实机功能验收

| ID | 操作 | 验收 |
|---|---|---|
| H01 | 连接与只读状态 | 匹配当前 SuperKVM；固件查询可失败但不乱发旧 GET_INFO |
| H02 | 人工点击/双击/拖动/滚轮/边界点 | 目标 UI 与预期一致，结束后无按住状态 |
| H03 | ASCII、符号、Ctrl+A、Alt+Tab、Ctrl+Alt+Del | 在明确测试环境按实际目标结果确认；输入法前置条件记录 |
| H04 | MCP 截图→定位→单次输入→新截图 | 真实图片内容可读，basis 对应坐标，不能靠本机桌面截图冒充 |
| H05 | agent 长输入中人工接管，旧工具继续调用 | 人工正常输入，旧工具 CONTROL_REVOKED，画面持续可看 |
| H06 | 页面关闭、桥退出、设备重插、目标分辨率变化 | 符合状态机，重新观察/申请，不重放旧动作 |
| H07 | 稳定性连续运行 60 分钟 | 无队列/句柄/线程持续增长；记录内存、CPU 与异常 |

滚轮、拖动、相对鼠标与设备断连释放必须分别在本应用验证，不能由键盘正常或串口写出推断通过。

## 6. 性能目标与测量

以下是首版工程目标，不是已测能力或用户已承诺的 SLA。若无法达到，先记录分段测量与原因，再明确调整设计/门槛，不能把 requested FPS 当结果。

| 指标 | 初始目标 | 测量边界 |
|---|---|---|
| 1080p 实际采集 | 同机相同配置持续 >=9fps；与实际测得基线比较 | 捕获成功帧的单调时间差，至少 5 分钟 |
| 视频积压 | 每连接 <=1 待发帧，不因慢 viewer 持续增加帧龄 | 对比抓帧、编码、发布、浏览器显示时间 |
| 输入排队到开始写 P95 | 正常负载 <50ms | 服务端收到有效请求至 actor write 开始，不含模型推理/目标 UI |
| 人工接管正常路径 P95 | <500ms；2 秒未完成屏障明确失败 | 请求到中和报告完整写入并确认，不等于物理 ACK |
| 当前图片可用帧龄 | 默认 <=1000ms；2 秒停帧撤销 | capture monotonic 时刻，不用 HTTP 返回时间冒充 |
| 首帧 | <=10 秒，记录实际冷/热启动值 | 选定设备打开到第一有效图 |
| 长期资源 | 热身后无持续增长趋势 | 每分钟记录 RSS/线程/句柄；缓存遵守硬上限，不能只看首尾一张截图 |

CPU/RSS/包体/启动时间先记录基线，不捏造绝对预算。对比无观看、一个观看者、观看+MCP截图、慢观看者四种负载。若视频耗 CPU，先定位采集解码/编码/复制，再判断是否替换原生 adapter；不把全部问题归因为 Python。

## 7. Windows 包验收

Portable：先运行 `scripts/build_portable.py`，再运行 `tests/integration/test_portable_package.py`。该用例解压真实 ZIP、从其他 cwd 启动托盘/MCP、迁移到中文和空格路径，并核对凭据轮换、人工保留与不写入个人 AppData；只使用模拟设备。

W01：通知区域无控制台，打开/全屏/接管入口可用。W02：重复启动与退出后句柄释放，路径含中文/空格，非管理员运行。W03：干净环境无预装 Python 可运行、页面无需外网、两种 EXE 的 stdio 行为正确。W04：只读诊断脱敏、日志轮转、许可清单完整、版本和锁文件可追溯。

## 8. 交付证据格式

公开验证摘要写入 [validation.md](validation.md)，只包含脱敏结论。私有原始证据另存仓库外；测试记录包含：测试 ID、commit、配置摘要、真实/模拟、开始结束时间、操作范围、预期/实际、通过/失败/未运行、证据位置、残留状态和清理结果。敏感内容不入 Git。

接手 agent 的完成报告须明确：哪些只通过单元/模拟、哪些通过真实 UI、哪些仍未测试。真实串口写成功不可替代 H02–H06 的视觉证据。
